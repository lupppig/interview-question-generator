# Interview Question Generator

A web app that takes a job title and returns 3 role-specific interview questions generated by Google's Gemini API.

## Stack

- **Backend:** FastAPI (Python) on Vercel serverless functions
- **Frontend:** Static HTML/CSS/JS served from `public/`
- **Model:** `gemini-2.5-flash` via the `google-genai` SDK
- **Cache:** Redis (any Redis-compatible URL via `REDIS_URL`)
- **Rate limiting:** SlowAPI, backed by the same Redis instance

## What the app does

`POST /api/generate` accepts `{ "job_title": "..." }` and returns three open-ended questions, each probing a distinct competency (behavioral, situational, technical). The prompt instructs the model to return JSON, which is enforced via `response_mime_type="application/json"` and parsed strictly — anything other than exactly 3 non-empty strings is rejected as an upstream error.

The Gemini call runs through `asyncio.wait_for` with a 25-second timeout so a hung upstream cannot stall a serverless invocation.

### File layout

```
public/             Static frontend (index.html, app.js, styles.css)
api/
  index.py          FastAPI app, /api/generate route, static mount
  cache.py          Redis cache with exact + phonetic lookup
  schemas.py        Pydantic request/response models and Settings
  errors.py         Domain errors and FastAPI exception handlers
vercel.json         Routes all traffic to the FastAPI function
```

### Caching

The cache is a two-tier lookup on Redis, designed so semantically equivalent inputs collapse onto one cached result:

1. **Exact key** — job title lowercased with whitespace collapsed (`iqg:questions:v1:<normalized>`).
2. **Phonetic key** — Double Metaphone code per word (`iqg:questions:phonetic:v1:<codes>`). This means `"Software Engneer"` and `"Software Engineer"` resolve to the same entry, as do common spelling drifts.

On a miss, the response is written under **both** keys, so future lookups hit on either path. TTL defaults to 7 days (`CACHE_TTL_SECONDS`). Redis failures are logged and swallowed — the cache is an optimization, not a source of truth, and the app falls back to calling Gemini directly.

### Rate limiting

`/api/generate` is capped at **5 requests/minute per IP** via SlowAPI. When `REDIS_URL` is set, SlowAPI uses the same Redis instance so the limit is shared across serverless invocations; otherwise it falls back to in-memory (per-instance) state. Rate-limited requests return a structured `429` response.

### Error handling

All routes raise domain exceptions (`ConfigurationError`, `UpstreamError`) which are mapped to JSON responses by handlers in `errors.py`. The handlers also normalize validation errors, rate-limit errors, and unhandled exceptions into the same `{code, message}` shape so the frontend has one error contract to deal with.

## Local development

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env   # set GEMINI_API_KEY, optionally REDIS_URL

uvicorn api.index:app --reload --port 8000
```

Then open <http://localhost:8000>. Without `REDIS_URL` set, caching is disabled and rate limiting is per-process — both features still work, just without shared state.

## Environment variables

| Variable | Required | Default | Purpose |
|---|---|---|---|
| `GEMINI_API_KEY` | yes | — | Google Gemini API key |
| `REDIS_URL` | no | _(empty)_ | Enables shared cache and rate-limit storage |
| `CACHE_TTL_SECONDS` | no | `604800` (7d) | TTL for cached question sets |

## API

`POST /api/generate`

```json
{ "job_title": "Customer Success Manager" }
```

Response:

```json
{
  "job_title": "Customer Success Manager",
  "questions": ["...", "...", "..."]
}
```

Error response (any failure):

```json
{ "code": "upstream_error", "message": "..." }
```
